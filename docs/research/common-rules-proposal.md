# Figma UI Agent 共通規則

> 外部提案原文（另一個 AI 依使用者委託撰寫，2026-10-03），原文保存。使用者於 2026-10-03 決定寫入 v1.9，並做以下調整後轉成 `.claude/skills/figma-ui/references/common-rules.md`：刪除「本文件優先於規格」；對比改為依產品政策（不全域移除）；SPACE-001 只套用在 agent 新建的節點、既有 pattern 數值優先；逐條規則的五種狀態不取代 gate 與完成判定的狀態；ADD 類與標 V 的規則不提問、列入 handoff；只在 Plan 與 Validate 載入。見規格 §9.6。

版本：1.0｜研究與審閱日期：2026-10-03｜語言：繁體中文

本文件供每次呼叫 Figma UI agent 時讀取，適用新稿、延伸設計及指定範圍的審查。優先度、自動化策略及預設數值為本專案政策；來源中的標準要求只適用於其指定情境。本文件是設計工作規則，不是完整 WCAG 合規清單。

## 1. 使用者決策與執行前提

- 每次先讀取本次需求中的產品、平台、設計系統及輸出範圍。平台未提及或有歧義時，必須先詢問使用者，不得預設 Web，也不得自動沿用上次平台。已明確提供的資訊不重問。
- 平台確認前可做共通盤點，但不得套用平台專屬尺寸、單位、安全區、手勢及斷點；跨平台需求應分別建立設定。
- 執行中遇到來源衝突、必要資訊缺漏或需要改變範圍時，先問使用者，再進行依賴該答案的工作；可繼續不受影響的檢查。
- 依使用者決定，原清單 P0 第 2 項「文字與必要圖形對比」不納入本文件，也不透過主題、焦點或其他規則重新加入對比門檻。保留「不能只靠顏色傳達資訊」。
- 與 FIGMA_UI_AGENT_SPEC.md v1.1 或其他舊文件同時使用時，本文件對「平台未提供才詢問」及「不納入對比檢查」的較新決策優先；其餘工程、授權、資源沿用及恢復契約繼續適用。
- 本文件需由呼叫流程明確載入；單獨新增 Markdown 不代表已安裝或啟用 agent。

## 2. 分級、修正權限與結果

| 類別 | 定義 |
|---|---|
| P0 | 適用時優先處理，避免無法理解、操作或完成任務 |
| P1 | 建立一致、可維護且能適應內容的設計 |
| P2 | 依任務情境提升理解與效率，不機械套用 |
| 標準 | 引用 WCAG 的 Web 條件；原生 App 須另查平台依據 |
| 指引 | 官方設計系統、Figma 文件或 UX 研究建議 |
| 政策 | 本專案選定的執行方式，不能宣稱為普遍標準 |
| A | 在既有授權範圍內，語意明確且驗證通過時可自動修正 |
| S | 提出設計建議；資訊不足或涉及取捨時先詢問 |
| V | 需要實作驗證；Figma 只驗證設計與交付註記 |

優先度不等於自動修改權限。唯讀審查只回報；不得為通過規則擅改共享主元件、建立另一套 tokens、拆離 instance 或擴大編輯範圍。已核准 DS 的特殊值先辨識為可能例外；若影響本次功能，提出衝突，不靜默忽略或改庫。

結果使用 pass、fail、needs_review、not_applicable、not_tested。not_applicable 必須附原因；缺少互動資訊或測試證據不得標 pass。每筆紀錄包含規則 ID、節點／流程、原值與新值、原因、例外、來源、驗證方式及結果。

## 3. P0：核心可用性

以下保留原清單除對比以外的所有 P0 規則，使用固定 ID 取代原序號。

| ID／規則 | 適用、判定與例外 | 處理／驗證 | 依據 |
|---|---|---|---|
| CORE-01 內容與操作可見 | 關鍵文字、錯誤訊息及主要操作不被意外重疊、裁切或浮層遮蔽；允許有意義的圖片裁切與可操作捲動 | A/S：讀取邊界並檢視畫面；不得一律關閉 Clip content | 政策、[S01] |
| CORE-02 點擊範圍 | Web 以至少 24×24 CSS px 為 AA 基準；按標準處理間距、等效控制、行內文字、原生控制及必要呈現例外。量測 hit area，不只量 icon；互相重疊的不同操作不可重複計入 | S/V：標出互動區；縮小目標不能只憑外框判定通過。原生 App 另查平台要求 | 標準、[S02] |
| CORE-03 鍵盤與焦點 | 提供焦點樣式、合理操作順序；Web 焦點不得被作者內容完全遮住。Modal 定義初始焦點、內部循環、關閉及返回合理位置 | S/V：檢查狀態與註記，實作測試 Tab、Shift+Tab、Escape 及各控制的標準鍵盤方式 | 標準／指引、[S03][S04] |
| CORE-04 不只靠顏色 | 錯誤、成功、選取與圖表分類具有文字、符號或其他辨識線索；重要 icon 操作註明可存取名稱 | S/V：檢查語意線索與實作名稱，不包含對比計算 | 標準、[S05] |
| CORE-05 縮放與重排 | Web 文字放大至 200% 不遺失內容／功能；一般垂直閱讀內容於 320 CSS px 寬可重排，必要二維表格、地圖等另處理；不將 320 當所有平台最小畫布 | A/S/V：窄版與長文字設計檢查；實作驗證瀏覽器縮放。文字間距由使用者調整後仍須可用，並非強制所有預設行高相同 | 標準、[S06][S07][S08] |
| CORE-06 表單與錯誤 | 標籤持續可辨識，不用 placeholder 取代；說明必填與格式，錯誤指出原因及修正方式，保留可用輸入 | S/V：檢查正常、錯誤與重試流程；涉及敏感資料保留策略時先確認 | 指引、[S09][S10] |
| CORE-07 回饋與復原 | 重要操作具有進行中、成功、失敗及適用的復原路徑；破壞性操作按後果決定確認或復原，不為每個動作加確認框 | S/V：逐步走查提交、失敗、重試及取消；成功畫面不得在尚未取得成功結果前顯示 | 指引／政策、[S01] |

## 4. P1：設計系統與布局

| ID／規則 | 適用、判定與例外 | 處理／驗證 | 依據 |
|---|---|---|---|
| SYS-01 優先沿用資源 | 使用現有元件、Variables、Styles；按語意綁定，不因數值相同就互換品牌與狀態 token | A/S：讀回元件關係、binding 及 mode 生效值；缺資源先詢問 | 指引／政策、[S11] |
| SPACE-001 間距尺度 | padding、固定 gap、明確頁面外距採核准 spacing tokens；沒有系統時才採 4px 基底 | A/S：依第 6 節處理，不直接改 token 定義 | 政策、[S12][S13] |
| SYS-03 布局與尺寸策略 | 規律列表、表單及操作群優先 Auto Layout；依內容選 Hug、Fill、Fixed、min/max；定位裝飾不強制改 Auto Layout | A/S：檢查文字增長、容器縮窄及項目增減；不得全部改 Fill | 指引／政策、[S12] |
| SYS-04 文字角色 | 建立／沿用標題、內文、標籤、說明及數據樣式，定義字體、字重、字級、行高；字級不受 4px 倍數限制 | A/S：檢查字型可用性及中英數混排；不得擅自替換缺失字型 | 政策 |
| SYS-05 元件狀態 | 依用途涵蓋 default、hover、focus、pressed、selected、disabled、loading、error 等；不要求每個元件全部具備 | A/S/V：建立適用狀態矩陣；觸控不可依賴 hover 才能完成操作 | 政策 |
| SYS-06 視覺一致 | 同角色的按鈕、欄位、圓角、邊框與 icon 沿用規格；一般、緊密與觸控密度可不同 | A/S：比較同角色／同密度元件；光學補償可註記例外 | 指引／政策、[S01] |
| SYS-07 響應式行為 | 定義何時換行、堆疊、收合、捲動及限制寬度；依內容決定斷點，不只交付幾張固定尺寸圖 | S/V：測斷點前後、長文字與大量項目，縮窄時不直接刪除重要功能 | 政策、[S12] |
| SYS-08 主題與模式 | 逐一檢查支援模式的 token 解析、文字／邊框／狀態語意及浮層呈現；不以換背景代表模式完成 | A/S：檢視各 mode 與截圖；此條不納入對比門檻 | 指引／政策、[S11] |

## 5. P2：理解與效率

| ID／規則 | 適用、判定與例外 | 處理／驗證 | 依據 |
|---|---|---|---|
| UX-01 操作層級 | 同一決策區域主要操作清楚；不強制整頁只能有一個主要按鈕 | S：按使用者當前任務走查 | 指引／政策、[S01] |
| UX-02 明確文案 | 按鈕描述實際動作，同概念用詞一致；避免含糊的「確定」及內部術語 | S：檢查動作、結果與各畫面用詞是否一致 | 指引、[S01] |
| UX-03 資訊分組 | 同組關係透過標題、對齊、距離等呈現；組內距離通常小於組間距離，但不得僅憑座標推定語意 | S：按內容關係審閱 | 政策 |
| UX-04 非理想情境 | 適用時提供空資料、無搜尋結果、載入、失敗、無權限及離線，說明原因與下一步 | S/V：狀態矩陣逐項檢查；與 CORE-07 共用回饋設計，不重複造元件 | 指引／政策、[S01] |
| UX-05 真實內容與語言 | 測長名稱、多行文案、日期、金額、翻譯膨脹；重要內容截斷時可取得全文 | A/S/V：以真實或明確標記的測試資料驗證，不任意縮小字級來塞入內容 | 政策 |
| UX-06 動效 | 動效說明狀態或空間變化，按用途設定時長，提供減少動態效果方案；有閃爍或自動播放風險時升至 P0，依適用條款查核 | S/V：審閱動態規格與實作；不把單一動畫時長當普遍標準 | 政策／標準、[S05] |

## 6. SPACE-001 自動修正細則

這是專案約定，不是 WCAG 或所有設計系統的共同要求；官方系統也可能有 2px 等間距。[S13]

1. 先確認平台與核准 DS。Figma 的 padding、gap 與頁面外距分別辨識，不假造所有節點都有 CSS margin 欄位。[S12]
2. 有 spacing tokens 時使用語意適用的核准候選；原有合法 binding 不因數值非 4 倍數就覆寫。沒有 DS 時可建議 `0、4、8、12、16、20、24、32、40、48、64` 等尺度；這是建議集合，不代表已獲准新增 variables。
3. 在合法且符合布局限制的候選中，選與原值距離最近者；等距預設取較大值。此策略可由本次需求覆寫。
4. 0 可用，但不可自動消除原本有意義的分隔。負間距、刻意重疊及極小光學補償交由例外判定，不套一般取整。
5. 不取整 Auto gap、比例或剩餘空間計算值、字級、描邊、向量路徑、圖片比例、平台安全區及核准例外。
6. 修改後檢查受影響父子層的溢出、換行、對齊、分組及互動區；不通過時嘗試下一個合法候選。沒有安全候選則還原該修改並回報。
7. 在沒有其他候選限制時，13→12、15→16、14→16。若 16 造成布局失效而 12 可用，14 可改 12，並記錄原因。
8. 預防浮點誤差：可採 0.01 Figma 單位作比較容差（專案政策），不得藉此將未知語意值視為合法。

## 7. 第二輪研究新增規則

只在相應功能存在時啟用；未提供該功能不需為了清單新增功能。標準條款按 Web 使用，原生平台另查其規範。

| ID／優先度／規則 | 判定、例外與處理 | 驗證 | 依據 |
|---|---|---|---|
| ADD-01／P0 拖曳替代操作 | 拖曳排序、看板搬移或滑桿提供單一指標、不需拖曳的等效操作，例如上移／下移、移至選單或數值輸入。只有鍵盤替代並不足以滿足此條。必要拖曳或未修改的使用者代理操作按條款處理 | S/V：比較兩種路徑結果 | 標準、[S14] |
| ADD-02／P0 Hover／Focus 額外內容 | 自訂 tooltip、子選單等應能不移走指標或焦點而關閉（如 Escape）；除非不遮蔽／取代其他內容，或用來傳達輸入錯誤。由 hover 觸發時，指標可移入額外內容而不使其消失。內容持續至觸發的 hover／focus 移除、使用者關閉或資訊失效；原生呈現按條款例外處理。必要資訊不得只在 hover 可得 | S/V：測移入提示、焦點、關閉及觸控替代；不以固定倒數過早隱藏 | 標準／政策、[S15] |
| ADD-03／P1 避免重複輸入 | 同一流程已輸入／提供而需再次填寫的資訊，自動帶入或提供可選取內容；必要、安全或失效資訊可例外。不強制跨 session 儲存資料 | S/V：走查前進、返回、修改與錯誤重試；不能只靠瀏覽器 autocomplete 代替流程處理 | 標準、[S16] |
| ADD-04／P0 可輔助的登入驗證 | 登入不可只依賴記憶／抄寫等認知測驗而沒有符合條款的替代或輔助；支援密碼管理器、自動填寫與貼上。條款另有物件辨識／個人內容例外；不把此規則誤寫成禁止密碼 | S/V：測登入、驗證碼與替代路徑；不強制新增特定登入服務 | 標準、[S17] |
| ADD-05／P0 可預期的輸入結果 | 改變欄位或選項，不在未預告時自動導頁、提交或改變使用情境；局部顯示相關欄位不一律視為違規 | S/V：測選取、輸入及焦點變化，必要時改明確提交或事前說明 | 標準、[S18] |
| ADD-06／P1 重要提交前核對與完成憑據 | 多步驟或後果重大的提交，提供適用的核對／修改路徑；完成頁說明已完成事項、參考編號（如有）及下一步。輕量即時操作不強制加核對頁 | S/V：修改後能返回核對，不丟失其他輸入；完成資訊可再次取得時註明路徑 | 指引／政策、[S19][S20] |

ADD-03 的 P1 是本專案處理排序，不代表來源的 WCAG A 要求可忽略；所有適用且採用的條款仍須列入交付狀態。ADD-06 擴充 CORE-07 的流程細節，共用一次驗證即可。

## 8. 品質審閱、修正循環與完成條件

1. 建立本次適用規則、平台、頁面、尺寸、主題及狀態矩陣；逐項說明不適用原因。
2. 先結構檢查，再看實際畫面與流程；數值合法不等於布局或 UX 良好。
3. 每輪先解決 P0，再 P1、P2。新增問題依影響重新分級，不為修整間距破壞關鍵操作。
4. 修正後重檢受影響規則及相鄰容器；相同輸入再次執行，不應產生來回修改或重複元件。
5. 每輪記錄問題、假設、改動與證據。仍未達條件時改用其他有依據的修正方式再驗證；不得只重跑同一失敗動作。遇到無新證據、規則互斥或必要資訊缺漏時先詢問，保留進度。
6. 設計交付完成須滿足約定範圍與設計可驗證條件；實作未測項目標 not_tested 並交付檢查方法，不把它們算 pass，也不據此宣稱完整 WCAG 合規。
7. 未解決的適用缺陷與已接受例外分開列出。例外需有理由、影響及接受紀錄；不能由 agent 自行將失敗改成例外來通過。

### 文件本次審閱結果

- 覆蓋檢查：保留原清單 21 條規則，移除指定的對比項；新增 6 條情境規則。
- 誤用檢查：區分 Web 數值與原生平台；平台未提供先問；不將 Figma 截圖當作實作驗證。
- 自動修正檢查：補上語意 token、等距、0、負間距、浮點容差與布局回歸；不全域取整。
- 重複檢查：提交核對／完成憑據與回饋規則共用驗證；狀態矩陣不重複造元件。
- 範圍檢查：主題與焦點規則沒有重新加入已排除的對比門檻。
- 證據限制：本次完成的是文件與來源審閱，尚未用真實 Figma 任務驗證規則誤報率或自動修正效果。

### 後續按需求研究

確認實際平台後，補查原生觸控目標、文字縮放、安全區及系統導覽；確認產品後，研究高密度表格、複雜圖表或多語／RTL 等需要的專門規則。若有媒體或限時流程，再補媒體替代內容、暫停與時間限制要求。這些條目目前是待研究項，不冒充已完成的規則。
