## 2. 實作內容

### 2.1 略過題目的判定（DEC-08、INVARIANT-28）

- **Schema**：
  - designDecision 新增 `skippedBy: user | agent`；`confirmation` 新增 `user_skipped`（共用定義 `common.schema.json#/$defs/rowConfirmation`）。
  - 一致性：`skippedBy` 只能出現在 `skipped`；`user_skipped` 需要 `skippedBy: user`；`skippedBy: user` 需要 `confirmation: user_skipped`。
- **判定**：
  - `validate-artifacts.mjs` 新增 `decisionResolved()`。`evaluate-completion` 只把 `skippedBy: user` 算已解決；`agent` 與沒有 `skippedBy` 的舊紀錄仍是待答。
  - 原因寫成 `dd-12=skipped(by agent)`。
  - 被略過的決策仍不能當 basisRef，兩種略過都一樣。
- **run-context**：使用者略過的列進 `confirmed`，不重問。

### 2.2 動態行為不問（DEC-11）與 handoff 第 12 項

- **Schema**：`plan.undefinedBehaviors` 新增（`id`、`behavior`、`kind`、`screenKey`、`note`），ID 不得重複。
- **handoff**：新增「未定義，交由實作決定」段，列出動態行為與使用者明確略過的決策和影響。agent 略過的決策留在「待決與未驗證」。
- **skill**：`SKILL.md` 與 `references/design-decisions.md` 寫明這類問題不提問、不建 designDecision。

### 2.3 範圍與授權類的列也記確認方式（DEC-09）

- `plan.decisions` 新增選填的 `confirmation`。
- `run-report.mjs metrics`：
  - `prefilledConfirmed`、`userModified`、`userFilled`、`userSkipped` 改為設計決策加上範圍／授權列的合計。
  - `confirmationByKind` 分開列兩種列。
  - 另外新增 `skippedByUser`、`skippedByAgent`、`undefinedBehaviors`。
- handoff 量測段多一行「確認方式」。v1.7 run 中 variables library 那列的「改過」，這樣就會算進去。

### 2.4 v1.7 run 的自動化問題（§20）

| 問題 | 修正 |
|---|---|
| `preflight.mjs diagnose` 只接受扁平格式 | `normalizeWhoami()` 接受扁平 `{plans}`、外層包裝（`whoami`／`result`／`data`…）、MCP text content 與 JSON 字串。找不到 plans 時回 `unrecognized_format`（exit 3，「格式不符」），不是 `blocked`，也不附帳號恢復步驟 |
| schema 要逐欄試錯 | 錯誤訊息直接附正確格式：`brief.viewports`、`limits.*`、`environmentDiagnosis`、evidence `toolRef`（讀取 operationId 放 `operation`）。`environmentDiagnosis.note` 改為接受。新增 `scripts/artifact-skeleton.mjs <contract> <run-id> [--write]`，6 種 artifact 的骨架都通過 schema，並附常見欄位範例；`--write` 不覆寫既有檔。`validate-artifacts` 有 schema 錯誤時輸出 `hint`；`preflight write-capabilities` 寫入前先驗證 |
| verify 後 `ledger.entities` 沒寫 | `verifyOperation` 自動寫入或更新（每個 logicalKey 一筆：根節點、childNodeIds、fingerprint、lastOperationId），並更新 `lastVerifiedOperationId`。類型只取讀回提供的 `entity.type`，沒有就記 `UNKNOWN`，不猜。`noChange` 的寫入不建 entity。handoff 列出所有 active entity，以及已驗證 write 建立與修改的節點數 |
| nativeWrite 要手動升級 | 第一個寫入讀回驗證成功後，`nativeWrite` 自動改成 `verified`（`basis: this_run`，evidence 是 op 與讀回）。`noChange` 的寫入不升級 |
| 同一階段重複記錄 | `recordPhase` 遇到同一階段再進入時不新增紀錄，保留第一次進入的時間。舊資料若有負的耗時，改記 `null` 並列入 `unknown` |

### 2.5 Figma plugin 版本檢查（§4.2.2）

- **`verify-installation.mjs`**：
  - 讀本機版本：`claude plugin list`，或 `installed_plugins.json` 加上 plugin 目錄的 `.claude-plugin/plugin.json`。
  - 從 `figma/mcp-server-guide` 的 `.claude-plugin/plugin.json`（main）取最新版，逾時 8 秒，`--offline` 可略過。
  - 輸出 `pluginVersion`（name、installed、latest、status、checkedAt、synced、source、note）。每次都重查，沿用的診斷也一樣。
  - 查不到最新版時只提示，不算 problem。
- **`capabilities.server.pluginVersion`**：新增到 schema。`preflight write-capabilities` 沒拿到這項時，取上次診斷的結果。
- **`run-context.mjs`**：
  - 本機版本較舊時，把 `kind: plugin_version` 放在 `ask` 最前面。
  - synced 時，題目註明「本機不一定能自行升級」，選項是 `wait_for_sync`／`use_current`；一般安裝的選項是 `upgrade_first`／`use_current`。
  - 答案記在 `brief.pluginVersionChoice`（新增到 schema），只限本 run；新 run 或最新版又更新時會再問。
  - `latest_unknown` 只在 notices 加一行。
- **實測（E，2026-10-03）**：本機 `figma@synced` 2.2.118，官方最新 2.2.126，`status: outdated`、`synced: true`。

### 2.6 固定 Figma 連線（§4.2.3、INVARIANT-27）

- **`preflight.mjs connections`**：從本 session 的工具名稱列出所有 Figma 前綴（`figmaConnections()`）。一個 → 直接推薦；多個 → `needsUserChoice`，推薦帳號檢查通過的那個。
- **capabilities**：`server.toolPrefix` 已是必填；新增 `otherFigmaPrefixes`。
- **`pre-figma-call.mjs`**：active run 期間：
  - 寫入（`use_figma` 的 `mode=write`，或非 `use_figma` 的 Figma 寫入工具）走的前綴和 `toolPrefix` 不同 → 阻擋，並給出正確的工具名稱。
  - `toolPrefix` 尚未記錄 → 寫入一律阻擋。
  - 讀取經其他前綴 → 放行，並在 hook-events 記 `PreToolUse:otherConnection`。
  - 放行仍然不輸出 `allow`（INVARIANT-14）。
- **hooks matcher**（發現並修正一個實際缺口）：
  - 原本的 `mcp__.*figma.*__(…)` 區分大小寫，**沒有涵蓋 claude.ai 連接器的 `mcp__claude_ai_Figma__*`**。
  - 改為 `mcp__.*[Ff]igma.*__(use_figma|create_new_file|upload_assets)|mcp__.+__use_figma`。後半段讓名稱不含 figma 的連線，它的 `use_figma` 也受保護。記錄用 hook 同樣調整。
  - `verify-installation.mjs` 新增 `matcherCoverage()`：以已知前綴加上 `claude mcp list` 實際列出的前綴測試每個 hook。`use_figma` 沒被涵蓋算 problem，其他寫入工具沒被涵蓋列為 notice。
  - `parseMcpList` 修正：名稱可含 `:` 與空白，例如 `plugin:figma:figma`、`claude.ai Figma`。

## 5. 假設與未驗證（INVARIANT-16）

- **plugin 連線的前綴**：寫成 `mcp__plugin_figma_figma__`，是依 claude.ai 連接器（`mcp__claude_ai_Notion__`）與手動連線的命名規則推得，**未在 session 中實際看到**。matcher 的 `mcp__.+__use_figma` 讓這個推論錯了也仍然涵蓋 `use_figma`。
- **matcher 的比對方式**：Claude Code 是整段比對還是部分比對，沒有另外驗證。`matcherCoverage` 以整段比對（較嚴格的讀法）檢查。
- **skill 規則的強制力**：只靠模型自律；能否用 Claude Code 設定硬性阻擋，仍未驗證（§4.7）。
- **`design` plugin 的連線**：沒有出現在 `/mcp`，推測是相同網址不重複建立，未驗證。本次 `verify-installation` 實際只列出 `figma`（`mcp__figma__`）一個 Figma 連線。
